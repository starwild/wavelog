# 需求规划 · Wavelog 中国 HAM 版

> 状态：草案 v0.1 ｜ 分支 `china-ham` ｜ 决策人：老大
> 上游：wavelog/wavelog（CI3 / PHP 8.x）

---

## 1. 定位

不是「汉化补丁」，是**面向中国大陆通联场景的日志前端**。三条主线：

| # | 主线 | 一句话 | 上游差距 |
|---|---|---|---|
| A | 双方设备 | 一条 QSO 里同时记下我和对方的电台/天线/功率 | 只有 `COL_RIG`（对方电台）、`COL_MY_ANTENNA`（我方天线，界面不可编辑）；**对方天线 ADIF 无字段** |
| B | 中国卡片要素 | 天气、温度、中继参数、区县、卡片编号等国内 QSL 卡常见栏目 | 全部缺失，且 **ADIF 3.x 没有天气类字段**，只能自定义 |
| C | 口述 / 识别录入 | 说一句话或贴一段文字/一张图，自动填好 QSO 表单 | 无任何语音/OCR 能力，也无文本解析入口 |

**不做的**：不做移动端 App、不改 CI3 框架、不引入前端构建链、不做奖状计算（沿用上游）。

### 3.1 复用现有列（只补 UI，不改 schema）

| 语义 | UI name | DB 列 | ADIF | 现状 |
|---|---|---|---|---|
| 我方电台 | `my_rig` | `COL_MY_RIG` | `MY_RIG` | 有列，界面不显示（CAT 自动写） |
| 我方天线 | `my_antenna` | `COL_MY_ANTENNA` | `MY_ANTENNA` | 有列，**界面不可编辑**，需补 |
| 我方功率 | `transmit_power` | `COL_TX_PWR` | `TX_PWR` | 已有，取自 station_profile 默认值 |
| 对方电台 | `rig` | `COL_RIG` | `RIG` | 有列，界面不显示，需补 |
| 对方功率 | `rx_pwr` | `COL_RX_PWR` | `RX_PWR` | 有列，界面不显示，需补 |
| 省/直辖市（对方） | `input_state` | `COL_STATE` | `STATE` | ADIF 3.1.3 起支持中国两字母码（`BJ`/`GD`/`SH`…），上游迁移 173 已内置枚举 |

| 市（对方） | `qth` | `COL_QTH` | `QTH` | 已有 |

> 结论：**双方设备 6 个位置里 5 个已有列**，只是界面不给。P0 的实数工作量在表单和 ADIF 补齐，不在 schema。

### 3.2 新增列（迁移 308）

| 语义 | UI name | DB 列 | 类型 | ADIF 导出 | 说明 |
|---|---|---|---|---|---|
| 对方天线 | `rig_ant` | `COL_RIG_ANT` | VARCHAR(255) | `APP_WAVELOG_RIG_ANT` | 无标准字段，只能自定义 |
| 对方区县 | `cn_district` | `COL_CN_DISTRICT` | VARCHAR(64) | `APP_WAVELOG_CN_DISTRICT` | `CNTY` 是美国县，不能复用 |
| 天气 | `cn_wx` | `COL_WX` | VARCHAR(16) | `APP_WAVELOG_WX` | 枚举：`SUNNY/CLOUDY/OVERCAST/RAIN/SNOW/FOG/WIND`，UI 显示晴/多云/阴/雨/雪/雾/大风 |
| 温度 | `cn_temp` | `COL_WX_TEMP` | SMALLINT NULL | `APP_WAVELOG_WX_TEMP` | 单位 ℃；**NULL = 未填，不用 0** |
| 中继/直频 | `cn_rpt` | `COL_RPT` | VARCHAR(64) | `APP_WAVELOG_RPT` | 自由文本，建议格式 `439.050 -5 T88.5` |
| 亚音 | `cn_ctcss` | `COL_CTCSS` | VARCHAR(16) | `APP_WAVELOG_CTCSS` | `T88.5` / `TSQ 88.5` / `DCS 023` |
| 卡片编号 | `cn_card_no` | `COL_CARD_NO` | VARCHAR(64) | `APP_WAVELOG_CARD_NO` | 纸质卡流水号 |

### 3.3 ADIF 映射的三条铁律

1. **`APP_` 字段名必须全大写**，形式 `APP_{PROGRAMID}_{FIELD}`，且 `{PROGRAMID}` 与文件头一致（上游当前是否写 `PROGRAMID` 待核，若无，本次一并补上 `WAVELOG`）。
2. **不进 `AdifHelper::$normalFields`**。那数组的规则是 `COL_{tag}` 硬绑定（`AdifHelper.php:149`），塞进去会取空。自定义字段一律按 `249-253` 行的显式写法单独输出。
3. **0 值会被吞**：`getAdifFieldLine()` 对 `''`/`null`/`0` 不输出。温度 0℃ 是真值 → 用 NULL 表示未填，导出侧对该字段单独判 `!== null`。

### 3.4 RST 的现实

上游 `COL_RST_SENT/RCVD` 是字符串，够用：语音 `59`、CW `599`、自报 `59+`、数字模式 `-12`（WSJT-X dB）。**不改类型**，但 UI 提示要写清 `59` 与 `-12` 两种语义，避免用户被校验拦。

## 4. 用户故事与验收

### US-1 双方设备成对录入（P0）
**作为** DX 爱好者，**我要**在一条 QSO 里同时看到我和对方的电台/天线/功率，**以便**日后复盘「这套组合通了多远」。

- 新建页与编辑页都有「双方设备」折叠块，两列布局：左「我方（MY）」右「对方（THEIR）」。
- 我方默认值来自 station_profile（功率已有；电台/天线新增 `station_rig` / `station_antenna` 默认列——**待决策 D3**），对方默认空。
- 保存后详情页、编辑回显、ADIF 导出/导入 round-trip 均不丢。
- 验收：填满 6 项 → 保存 → 编辑回显一致 → 导出 ADIF 含 `MY_RIG/MY_ANTENNA/TX_PWR/RIG/RX_PWR/APP_WAVELOG_RIG_ANT` → 再导入新库字段一致。

### US-2 中国卡片要素（P0）
**作为** 卡片管理员，**我要**记天气/温度/中继/区县/卡片编号，**以便**卡片和日志对得上。

- 折叠块「卡片要素」，7 个字段，全部可空。
- 天气是下拉（中文显示），温度数字输入带 `℃` 后缀，中继/亚音带格式示例占位符。
- 验收：同上 round-trip；天气 UI 中文 ↔ DB 枚举 ↔ ADIF 枚举 三者可逆。

### US-3 文本口述解析（P0，纯前端零依赖）
**作为** 边听边记的操作员，**我要**贴一句「BG1ABC 十四兆 单边带 五九 北京」就自动填表。

- 录入页新增「快速解析」输入框（textarea + 解析按钮），支持粘贴聊天记录、Spot 文本、自己打的一段话。
- 解析出字段后**先高亮回显**「我识别到：呼号 BG1ABC / 20m / SSB / 59 / 北京」，用户点「填入」才落到表单。
- 无法识别的字段保持原值，**不覆盖用户已填内容**（除呼号冲突时提示）。
- 词表与归一规则见 §6。

### US-4 语音输入（P1，有前置风险）
**作为** 手持麦克风的操作员，**我要**说一句就填表。

- ⚠️ **前置风险（必须老大拍板 D1）**：`webkitSpeechRecognition` 在 Chrome 上依赖 Google 语音服务，**中国大陆基本不可用**；Edge 走微软服务，可用性也不稳。
- 因此 P1 采用「能力探测 + 三级降级」：浏览器 API 可用则用；否则引导用户用系统输入法的语音键把文字打进 US-3 的文本框；再否则接本地 ASR 服务（可选配置）。

### US-5 卡片照片 / 截图识别（P2）
**作为** 事后回填的人，**我要**丢一张 QSL 卡照片，自动识别出呼号和主要要素。

- ⚠️ **现实约束**：Tesseract.js 对**手写卡片基本无解**，只对印刷体/电子 QSL/屏幕截图有效。需求上明确标注「仅印刷体」。
- 识别结果必须进**确认面板**（逐字段可编辑、可勾选采用），**禁止直接落库**。
- 可选云端视觉兜底（需 API key，走 config 不进仓库）。

### US-6 中继记录（P0 字段 / P1 数据）
- P0：`cn_rpt` + `cn_ctcss` 自由文本，满足「记下来」。
- P1：结构化（上行/下行/差频/亚音） + 常用中继库（自建表，可导入 CSV）。**待决策 D4**。

## 6. 解析引擎规格（核心可复用资产）

一套 parser，三个入口（文本 / 语音 / OCR）共用。放 `assets/js/sections/cn_qso_parser.js`，纯函数、无 DOM 依赖、可单测（node 跑）。

### 6.1 目标字段
`callsign` `band` `freq` `mode` `submode` `rst_sent` `rst_rcvd` `qth` `locator` `rig` `rig_ant` `tx_pwr` `rx_pwr` `cn_wx` `cn_temp` `cn_rpt` `cn_ctcss` `cn_card_no`

### 6.2 归一规则（举例）

| 输入 | 输出 | 规则 |
|---|---|---|
| `五九` / `五九加` / `59` / `5.9` | `59` / `59+` | 中文数字表 + 信号报告专用词表 |
| `五九九` | `599` | 同上，长度 3 判 CW |
| `十四兆` / `14.200` / `14200` | `14.2` → `BAND=20m` | 数值域判定（1.8–1300）+ 波段表反查 |
| `单边带` / `话` / `USB` | `SSB`（submode `USB`/`LSB` 按频率推） | 模式词表 |
| `报务` / `等幅报` | `CW` | |
| `数字` / `FT8` | `FT8` | |
| `一百瓦` / `100W` / `100` | `100` | 中文数字 + 单位剥离 |
| `北京` / `京` | `STATE=BJ`、`QTH=北京` | 省市表（含简称、地级市 → 推断省） |
| `朝阳区` | `cn_district=朝阳区` | 区县后缀词（区/县/旗/市） |
| `439.050减5` / `439.050 -5 T88.5` | `cn_rpt=439.050 -5`、`cn_ctcss=T88.5` | 中继表达式 |
| `晴` / `多云` / `下雨` | `SUNNY` / `CLOUDY` / `RAIN` | 天气词表 |
| `25度` / `零下3度` | `25` / `-3` | 温度表达式 |

### 6.3 呼号识别
优先级最高，先抽出呼号再从剩余文本里找其他字段（避免把 `BG1ABC` 里的 `1` 当功率）。
正则：`/\b(?:[A-Z]{1,2}\d[A-Z]{1,4}|B[GJ-R]\d[A-Z]{1,4})\b/i`；再做 ITU 前缀校验（用现有 `Dxcc` 数据兜底）。
**不做**：不做呼号纠错（`BG1ABC` ↔ `BG1ABc` 之外的模糊匹配交给人）。

### 6.4 置信度与冲突
- 每个检出字段带 `confidence: high|low`（规则命中 = high，模糊匹配 = low）。
- 回显面板用颜色区分，low 的字段默认**不勾选**。
- 与表单已有值冲突时：以用户已在表单里手填的为准，解析结果只填空白字段（呼号例外，冲突时弹确认）。

## 11. 口径备忘（容易被问到的）

- **时间一律存 UTC**，UI 显示可切本地时区；这是 ADIF 硬约束（`TIME_ON` 无时区字段）。
- **RST 是字符串**，`-12` 合法，别加数字校验。
- **中国省码**用 ADIF 官方两字母码（`BJ GD SH …`），不是拼音/数字。
- **业余分区（1–10 区）没有 ADIF 字段**，只能由呼号推导，不建议落库（推导即可）。
- **`RX_PWR` 是对方的功率**，不是「我收到的功率」，字段命名别搞反。
